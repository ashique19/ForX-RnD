(3) DD VIA SIZING (written hypothesis, not a yaml change)
---------------------------------------------------------
- Hypothesis: drawdown is driven by loss clustering and same-currency stacking,
  not by any single trade. Two ways to cut it:
  - cut size after losses (e.g. halve after 2 consecutive losses, restore after
    a win);
  - cap total exposure and per-currency exposure (e.g. max 1 open position per
    currency leg, max N open overall). This is the study's "book risk budget".
- Judged on: the holdout plus bootstrap worst-case DD (block bootstrap of
  holdout trade returns, 95th-percentile max DD). It must not lower holdout
  expectancy per unit risk.
- How it differs from the BANNED size-by-conf:
  - size-by-conf scaled size UP on model confidence, i.e. it bet on the signal
    being calibrated, which it is not;
  - this rule scales size only from realized book state (recent losses, open
    exposure). It never sizes up and never uses model confidence.

(4) NEW FEATURES ONE AT A TIME (holdout only)
---------------------------------------------
Each feature gets a written mechanism hypothesis before any run, one feature
per run, judged on the holdout only.
- a) Rate differential / carry: the policy-rate spread sets a drift and a
  funding cost for multi-hour holds.
- b) Trend-vs-range regime: barrier wins should depend on whether the pair is
  trending (ADX/efficiency ratio) or ranging. This is distinct from the banned
  ADX skip-chop gate, because here it is a feature, not a gate.
- c) Session timing: liquidity and volatility differ by session, so barrier
  hit rates should too. Hour Fourier terms already exist; the new feature must
  add something they don't.
- d) USD strength index: a common USD factor drives the USD pairs. Use a
  basket of the watchlist USD legs, computed causally.
